# ADR-0001：后端采用模块化单体

## 状态

Accepted

## 背景

项目处于早期，由小团队快速迭代，同时已经出现账号、资料、同步、错题和额度等明确边界。微服务会引入网络、部署、追踪和一致性成本。

## 决策

使用 Node.js + TypeScript 构建模块化单体 API。模块共享一个部署单元和 PostgreSQL 数据库，但只能通过公开服务接口跨模块调用。

## 结果

优点是部署和本地调试简单、事务边界清晰、未来可按真实负载拆分。缺点是单次部署影响整个 API，模块约束需要通过代码结构和测试维持。

## 备选方案

- 微服务：当前规模下运维成本过高。
- 纯 Serverless：对长上传和厂商无关目标不友好。
